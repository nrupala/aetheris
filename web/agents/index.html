Aetheris Agent Orchestrator — Documentation

Overview

Multi-agent orchestration system with MCP (Model Context Protocol) server, A2A (Agent-to-Agent) protocol, and cross-engine orchestration. Agents collaborate through a planner-coordinated workflow with OPA-gated access to RAG, KG, and file systems.

Access

  • URL: https://agents.nrupalakolkar.com
  • Auth: HTTP Basic Auth — credentials required
  • Connection: Cloudflare Tunnel (encrypted, no open ports)

Architecture

Browser → Cloudflare Edge → Tunnel → Nginx (auth + proxy)
  → Rust Core (:8080) — Agent orchestrator, MCP, A2A, workflow engine
    → Python Orchestrator (:9090) — Cross-engine state (optional)
      → Ollama (:11434) — LLM inference for all agents

Agent Roles

  • Planner — Decomposes complex tasks into sub-tasks, coordinates multi-agent workflow execution, assigns work to Researcher → Coder → Reviewer pipeline
  • Researcher — Queries RAG with iterative reasoning loop, extracts entities to Knowledge Graph, validates sources
  • Coder — Uses RAG context + KG relationships for code generation, applies project conventions
  • Reviewer — Evaluates outputs against KG history + RAG standards, validates quality and compliance

Workflow Pipeline

The standard execution flow is: Planner → Researcher → Coder → Reviewer

Each agent executes sequentially, passing context forward. The Planner decomposes the task, the Researcher gathers information, the Coder produces output, and the Reviewer validates it.

Tabs

  • Dashboard — Summary stats (agents, tasks, memory forecast, cross-system health) and active task list
  • Workflow — Run multi-agent workflows with task input and execution progress
  • Agents — Detailed agent pool view with role, model, state (idle/executing/failed), tasks completed, policy compliance
  • Cross-System — Cross-engine state showing connected engines, resource spread forecast, and recommendations
  • MCP Tools — Model Context Protocol tools available for agent use
  • A2A Log — Agent-to-Agent message log with flow, type, approval status, and timestamps

Agent Lifecycle

  • Idle — Agent is initialized and waiting for a task assignment
  • Executing — Agent is actively processing a task (calling LLM, querying RAG, writing code)
  • Complete — Agent finished the task successfully; result is passed to the next agent in the pipeline
  • Failed — Agent encountered an error; task is marked with error details

API Reference

All endpoints accessible at https://agents.nrupalakolkar.com/

GET /api/agents/status

Status of each agent in the pool: role, model, state, tasks completed, policy checks allowed/total.

curl -u user:pass https://agents.nrupalakolkar.com/api/agents/status

POST /api/workflow/run

Run a multi-agent workflow with optional reasoning and max iterations.

curl -u user:pass https://agents.nrupalakolkar.com/api/workflow/run \
  -H "Content-Type: application/json" \
  -d '{"task": "Refactor the auth module", "max_iterations": 3, "use_reasoning": true}'

POST /api/task/submit

Submit a single-agent task for a specific role.

curl -u user:pass https://agents.nrupalakolkar.com/api/task/submit \
  -H "Content-Type: application/json" \
  -d '{"role": "researcher", "task": "Find documentation about ZFS encryption"}'

GET /api/mcp/tools

List all MCP tools with names, descriptions, and tags.

GET /api/a2a/messages

Retrieve recent A2A messages showing inter-agent communication flow.

GET /api/orchestrator/state

Cross-engine orchestration state: connected engines, response times, active tasks, memory usage, queue depth.

GET /api/orchestrator/forecast

Resource spread forecast: predicted memory, host utilization, confidence score, bottleneck analysis, recommendations.

GET /api/health

Overall health: agent count, task count, tools, prompts, cross-system status, spread forecast.

MCP (Model Context Protocol)

MCP provides a standardized interface for agents to interact with tools and external systems. The MCP server exposes tools that agents can discover and invoke dynamically.

Available tool categories include file operations, RAG queries, knowledge graph access, code evaluation, and system commands — all gated through OPA policy checks.

A2A (Agent-to-Agent)

A2A messaging enables direct communication between agents for coordination, handoff, and result sharing. Messages flow through a channel-based gateway with approval tracking.

Each A2A message includes: source agent, target agent, message type, payload, approval status, and timestamp.

Policy Enforcement

All agent actions are gated through an OPA (Open Policy Agent) policy check. The BaseAgent base class evaluates every tool call against configured policies before execution. Policy stats show allowed vs. total checks per agent.
