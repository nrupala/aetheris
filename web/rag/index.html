📘 Aetheris RAG — Documentation

Overview

Aetheris RAG (Retrieval-Augmented Generation) enables you to upload documents and ask questions about their content. It uses vector embeddings and semantic search to find relevant passages, then generates answers using your local LLM.

Access

  • URL: https://rag.nrupalakolkar.com
  • Auth: HTTP Basic Auth — rag_user / BCjfTYIIjMASFGVM
  • Connection: Cloudflare Tunnel (encrypted, no open ports)

Architecture

Browser → Cloudflare Edge → Tunnel → Nginx (auth + proxy)
  → Rust Core (:8080) — API gateway, proxies /query, /ingest, /sources
    → Python Orchestrator (:9090) — RAG pipeline, embeddings, vector store
      → Ollama (:11434) — LLM generation (qwen2.5:14b)
📄 Document Upload → → 🔪 Text Chunking
🔪 Chunks → → 🧮 Embedding Generation
🧮 Embeddings → → 💾 Vector Store (SQLite + chroma)
❓ Query → → 🔍 Semantic Search (top-k)
🔍 Results → → 🤖 LLM Generation (qwen2.5:14b)
🤖 Answer → → 💬 Response with Sources

Reasoning Mode

When enabled, the RAG pipeline uses an iterative reasoning loop with temperature annealing (0.8→0.5→0.1) and self-verification to improve answer quality for complex questions.

  • Max Iterations: Maximum number of reasoning passes (1-10)
  • Confidence Threshold: Stop iterating when confidence exceeds this value (0.0-1.0)
  • Temperature Annealing: Automatically decreases temperature across iterations

Knowledge Graph

Entities and relations extracted from your documents are stored in a personal knowledge graph, enabling contextual awareness across queries.

How It Works

  1. Upload — Documents are split into chunks (~500 tokens each)
  2. Embed — Each chunk is converted to a vector using the embedding model
  3. Store — Vectors are saved in a SQLite database with metadata
  4. Search — Queries are embedded and matched against stored vectors
  5. Generate — Top-k relevant chunks are sent to the LLM for answer generation
  6. Cite — Source documents are returned with relevance scores

API Reference

All endpoints accessible at https://rag.nrupalakolkar.com/

GET /health

Check service status.

curl -u rag_user:BCjfTYIIjMASFGVM \
  https://rag.nrupalakolkar.com/health

POST /query

Ask a question against indexed documents.

curl -u rag_user:BCjfTYIIjMASFGVM \
  https://rag.nrupalakolkar.com/query \
  -H "Content-Type: application/json" \
  -d '{
    "query": "What is the project structure?",
    "use_rag": true,
    "reasoning": true,
    "max_iterations": 3,
    "confidence_threshold": 0.7,
    "top_k": 5,
    "threshold": 0.7,
    "include_history": true
  }'

POST /ingest/file

Upload and index a single file.

curl -u rag_user:BCjfTYIIjMASFGVM \
  https://rag.nrupalakolkar.com/ingest/file \
  -F "file=@document.pdf"

POST /ingest/directory

Index an entire directory.

curl -u rag_user:BCjfTYIIjMASFGVM \
  "https://rag.nrupalakolkar.com/ingest/directory?path=/config/workspace/docs"

GET /stats

Get knowledge base statistics (chunks, sources, DB size).

GET /sources

List all indexed documents with chunk counts and timestamps.

DELETE /sources/{path}

Remove a specific document from the index.

POST /reset

Clear all indexed data (irreversible).

Supported File Types

  • PDF — Extracted text with page metadata
  • TXT — Plain text files
  • MD — Markdown with formatting preserved
  • HTML — HTML with tags stripped
  • JSON — Structured data (stringified)
  • CSV — Tabular data with headers

Settings Explained

  • Top K: Number of most relevant chunks to retrieve (default: 5). Higher = more context but slower
  • Similarity Threshold: Minimum cosine similarity score (0.0-1.0). Higher = stricter matches
  • Model: LLM used for answer generation (pulled from AI service)
  • Reasoning Mode: Enables iterative self-verification for complex questions

Tips

  • Index first: Upload documents before querying
  • Chunk size: Large documents are automatically chunked
  • Threshold tuning: Lower threshold (0.5) for broader matches, higher (0.8) for precision
  • Reasoning mode: Use for complex, multi-part questions that require deeper analysis
  • Source tracking: Every answer shows which documents were used
  • Knowledge Graph: View entities and relations extracted from your documents
